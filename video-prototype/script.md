# 第1回 台本 —「時間術の本15冊の"紹介文"を分析したら、共通点がゼロだった」

チャンネル: **本のデータ研究所**
形式: 漫画風ポップアニメ + 女の子2人の掛け合い + VOICEVOX音声(顔出し・声出しなし)

**数値はすべて実データ。** 集計手順は `../analysis/START_HERE.md`、
抽出結果と名寄せ表は `../analysis/recovered/` にある。

### 動画の核になる主張

> 15冊の紹介文に共通点はなかった。でもそれは本がバラバラだからではない。
> **紹介文に中身が書かれていないから**だ。
> 同じ本でも、目次を見れば12個の具体策が出てくる。
> **紹介文で本を選ぶな。目次を見ろ。**

当初は「どの本も同じことを言っている」という仮説だったが、集計したら逆の結果が出た。
**仮説が外れた過程をそのまま動画にしている**のがこの回の価値。

## 使い方

```bash
# VOICEVOXアプリを起動してから実行すると、キャラ音声になる
python3 build_video.py ./build

# 必要パッケージ: brew install ffmpeg / pip3 install pillow numpy
```

出力: `build/sample_video.mp4` / `build/thumbnail.png` / `build/narration.wav` /
`build/chapters.txt`(概要欄に貼るチャプター)

### 尺の調整

VOICEVOXは読み上げが速いので、初回ビルドは7分41秒だった。
**8分未満だとミッドロール広告を入れられない**ため、次の2つで8分を超えるようにしてある。

- `speedScale` を 1.05 → **1.0**(数字の多い動画なので、速さより聞き取りやすさを優先)
- `LINE_PAUSE` を 0.34 → **0.40** 秒、`SCENE_PAUSE` を 0.8 → **0.9** 秒

尺を変えたいときはこの3つをいじる。

チャプターは音声の実測長から自動生成されるので、手で測る必要はない。
話者や台本を変えて尺が変わっても、ビルドし直せば自動で追従する。
区切り位置は `SCENES` の `chapter` キーで決まる。

## タイトル案(A/Bテスト用)

1. 時間術の本15冊の「紹介文」を分析したら、共通点がゼロだった
2. Amazonの紹介文で本を選ぶのをやめた方がいい理由【15冊分析】
3. 同じ本なのに、紹介文からは1個・目次からは12個だった話

## サムネ案

`build_video.py` が `build/thumbnail.png` を出す
(「共通点**ゼロ**だった」+ サブ帯「紹介文で本を選ぶな」+ 2キャラ)。

### ただし第1回はこれを使えない

カスタムサムネイルは**中級者向け機能**で、解除には**電話番号の確認が必須**。
同じ番号は他チャンネルで使用済みのため、現時点では認証できない。

- 上限は **1つの番号につき1年で2チャンネル**まで
- **他チャンネルを削除しても、番号の認証履歴は残るので枠は戻らない**
- 身分証・動画による確認は**上級者向け機能**の要件で、中級者向け機能(=電話番号の確認)が
  前提になっているため、電話番号を迂回する正規ルートは無い
- 前回の認証から1年経てば同じ番号を再度使える。使えるようになったら
  `build/thumbnail.png` に差し替える(サムネイルは公開後いつでも変更でき、
  差し替えても再生回数はリセットされない)

なお**サムネイルのA/Bテストは上級者向け機能**なので、電話番号の確認が通るまで使えない。

### 認証できるまでは自動サムネイルで出す

YouTubeは動画のおよそ **25% / 50% / 75%** の位置から3枚の候補を作る。
本編は全編が大きな文字のスライドなので、どの候補も文字は読める。
行数から見た各候補の中身は次のとおり(実尺は行の長さで多少ずれる)。

| 候補 | 位置 | 当たるシーン | 見え方 |
|---|---|---|---|
| 1枚目 | 約25% | #6「AIの分析、信用できるの?」 | 箇条書き。弱い |
| 2枚目 | 約50% | #12「本がバラバラだから、ではない」 | 集中線あり。中くらい |
| 3枚目 | 約75% | #17〜18「紹介文からは1個、目次からは12個」/「紹介文で本を選ぶな」 | **一番強い。これを選ぶ** |

自動サムネは弱いので、**第1回のクリック率はタイトルが担う**。
数字と結論を前に置いたタイトルを使うこと。

## 演出キー(第6回から。ep*.py の SCENES / lines に書く)

淡々と数字を読むだけだと「面白い瞬間」が生まれないので、予想→答え・表情・音・間を足した。
すべて任意。書かなければ従来どおり。

| 場所 | キー | 値 | 効果 |
|---|---|---|---|
| scene | `sfx` | `drum` / `ding` / `tada` / `boing` / `pop` / `swoosh` | シーンの頭で鳴る。numpyで合成するので素材不要 |
| scene | `impact` | `True` | 集中線 + 入った瞬間に画面が揺れる |
| line | `sfx` | 同上 | そのセリフの頭で鳴る |
| line | `pause_before` | 秒 | セリフの前の溜め(ドラムロール中に使う) |
| line | `speed` | 倍率 | 前置きは 1.05、答えは 0.92 くらい |
| line | `face` | `normal` / `surprise` / `smug` / `sad` | 話し手の表情 |
| line | `react` | 同上 | **聞き手**の表情(答えを聞いた瞬間の驚き、など) |
| visual | `type: "guess"` | `question` / `num` / `unit` / `label` / `reveal_line` | 「?」が脈打ち、`reveal_line` 番目のセリフで答えがポンと出る。出た瞬間に `ding` が自動で鳴る |
| visual | `type: "pipeline"` | `steps`(4つ) | 本→目次→主張→数える の手順アニメ。シーンの時間を4等分して順に点灯 |
| visual | `type: "prompt_compare"` | `request`(2行) / `example`(3行) | お願い文を左右に並べ、右の「見本」部分に蛍光ペンが引かれる。**専門用語を出したら、その直後に実物を見せる**ために使う |
| scene | `op` | `{"title": "回のタイトル"}` | **オープニング**(約3秒)。キャラが左右から入り、チャンネル名がポンと出て、キャッチコピーと回番号。`sfx: "jingle"` と組む |

### オープニングの置き場所

**0秒目に置かない。** フック(視聴者の状況 → 予想 → 答え)で掴んでから入れる。
冒頭にOPがあると、最初の数秒で「いつもの前置き」と判断されてスワイプされる。

```python
{"op": {"title": "AI本の1位を、試してみた"}, "sfx": "jingle",
 "visual": {"type": "op", "kicker": ""},
 "lines": [{"sp": "noa", "text": "本のデータ研究所!", "pause_before": 0.55, "speed": 1.05}]}
```

キャッチコピーは `build_video.py` の `TAGLINE`(「本を数えて、確かめる。」)。

### 「予想→答え」の型

```python
{"visual": {"type": "guess", "kicker": "…何ポイント上がった?", "question": "あなたは何ポイントだと思いますか?",
            "num": "2", "unit": "ポイント", "label": "48条件中、たった1条件ぶん", "reveal_line": 3},
 "lines": [
   {"sp": "mei", "text": "何ポイント上がったと思う?"},
   {"sp": "noa", "text": "20ポイントくらい?", "face": "smug"},            # 外れる予想を言わせる
   {"sp": "mei", "text": "答えは", "sfx": "drum", "pause_before": 0.3},   # ドラムロール
   {"sp": "mei", "text": "2ポイント", "pause_before": 1.1, "speed": 0.92, "react": "surprise"},  # ← reveal_line
   {"sp": "noa", "text": "2!?", "face": "surprise"},
 ]}
```

**視聴者にも予想させる**のがポイント(「見ている人も3秒考えて」)。予想と答えのズレが「面白い」の正体。
